01 — ProblemProblem

LLMs are unreliable calculatorsLLMs sind unzuverlässige Rechner

LLM-assisted trading systems share a structural flaw documented in recent literature (2025-2026): they treat the language model's output as a reliable, interpretable judgment — even though LLMs fail dramatically at precise numerical computation (a 2025 benchmark shows accuracy collapsing from 95.6% to near 0% between simple extraction and multivariate calculation) and suffer from correlated bias when the same model plays several contradictory roles in a debate.

KI-gestützte Trading-Systeme teilen einen strukturellen Fehler, der in der aktuellen Literatur (2025-2026) dokumentiert ist: Sie behandeln die Ausgabe des Sprachmodells als zuverlässiges, interpretierbares Urteil — obwohl LLMs bei präziser numerischer Berechnung dramatisch versagen (eine Benchmark aus 2025 zeigt einen Genauigkeitseinbruch von 95,6 % auf nahezu 0 % zwischen einfacher Extraktion und multivariater Berechnung) und unter korreliertem Bias leiden, wenn dasselbe Modell mehrere widersprüchliche Rollen in einer Debatte übernimmt.

Project goal: build a system that uses LLMs for what they do well — synthesis, adversarial argumentation, reading macro context — while structurally eliminating their use for anything that must be exact. One rule, applied throughout the codebase: the LLM interprets, the code computes.

Projektziel: ein System bauen, das LLMs für das einsetzt, was sie gut können — Synthese, kontroverse Argumentation, das Lesen von Makro-Kontext — und ihren Einsatz für alles, was exakt sein muss, strukturell ausschließt. Eine Regel, konsequent im gesamten Code angewendet: das LLM interpretiert, der Code rechnet.

03 — Key decisionsZentrale Entscheidungen

Technical choices, and whyTechnische Entscheidungen — und warum

01 — SEPARATION OF CONCERNS01 — TRENNUNG DER ZUSTÄNDIGKEITEN

Strict compute / interpretation splitStrikte Trennung von Berechnung und Interpretation

Every number in the final report (RSI, ATR, composite score, calendar event count, fundamental bias) is computed in deterministic Python. The LLM never produces a final score directly — it supplies atomic, sourced judgments that the code then aggregates through a transparent, auditable formula.

Jede Zahl im finalen Bericht (RSI, ATR, Kompositscore, Anzahl Kalenderereignisse, fundamentaler Bias) wird in deterministischem Python berechnet. Das LLM erzeugt nie direkt einen Endscore — es liefert atomare, belegte Einschätzungen, die der Code anschließend über eine transparente, nachvollziehbare Formel aggregiert.

02 — DYNAMIC FAN-OUT02 — DYNAMISCHER FAN-OUT

Configuration-driven, not hardcodedKonfigurationsgesteuert statt hartcodiert

The per-instrument debate uses LangGraph's Send mechanism (map-reduce pattern) instead of 26 hardcoded nodes — changing the tracked instrument list needs no change to the graph itself.

Die Debatte pro Instrument nutzt LangGraphs Send-Mechanismus (Map-Reduce-Muster) statt 26 fest codierter Knoten — eine Änderung der verfolgten Instrumentenliste erfordert keine Änderung am Graphen selbst.

03 — INDEPENDENT AUDIT03 — UNABHÄNGIGER AUDIT

Multi-provider, blind verificationBlinde Verifikation mit mehreren Anbietern

To mitigate the documented risk of a single LLM "debating with itself" (Bull/Bear/Judge from the same model), an auditor agent reconstructs each verdict blind — without seeing the debate's reasoning — using an independent LLM provider where possible (Kimi K3 / Moonshot AI, OpenAI as fallback), with graceful degradation and explicit transparency about the real independence achieved.

Um das dokumentierte Risiko zu mindern, dass ein einzelnes LLM "mit sich selbst debattiert" (Bull/Bear/Judge vom selben Modell), rekonstruiert ein Auditor-Agent jedes Urteil blind — ohne die Argumentation der Debatte zu sehen — nach Möglichkeit mit einem unabhängigen LLM-Anbieter (Kimi K3 / Moonshot AI, OpenAI als Fallback), mit gracefuller Degradation und expliziter Transparenz über die tatsächlich erreichte Unabhängigkeit.

04 — ANTI-LOOK-AHEAD BIAS04 — ANTI-LOOK-AHEAD-BIAS

Strict temporal maskingStrikte zeitliche Maskierung

Any data (economic calendar, price history) later than the simulated decision moment is strictly masked before it reaches an agent — a necessary condition for any future retroactive backtesting to be valid, not just for live use.

Jede Daten (Wirtschaftskalender, Kurshistorie), die nach dem simulierten Entscheidungszeitpunkt liegt, wird strikt maskiert, bevor sie einen Agenten erreicht — eine notwendige Bedingung dafür, dass zukünftiges retroaktives Backtesting valide ist, nicht nur für den Live-Einsatz.

05 — BUILT-IN STATISTICAL VALIDATION05 — EINGEBAUTE STATISTISCHE VALIDIERUNG

Not just raw performanceNicht nur reine Performance

backtest/scorecard.py computes a calibration table (does the displayed confidence score actually match the observed success rate?), a Brier score, comparisons against naive baselines (coin flip, trend following), and applies a walk-forward protocol to avoid overfitting when thresholds are tuned later.

backtest/scorecard.py berechnet eine Kalibrierungstabelle (entspricht der angezeigte Konfidenzwert tatsächlich der beobachteten Erfolgsquote?), einen Brier-Score, Vergleiche mit naiven Baselines (Münzwurf, Trendfolge) und wendet ein Walk-Forward-Protokoll an, um Overfitting bei künftiger Schwellenwert-Anpassung zu vermeiden.

04 — What sets it apartWas es unterscheidet

Not just an LLM wrapperKein bloßer LLM-Wrapper

The most significant part of this project isn't report generation — it's the critical audit cycle around it. A professional review of the system (referenced in the code and README) identified precise flaws drawn from recent quant/LLM literature (look-ahead bias, correlated debate bias, uncalibrated confidence score), and each fix was implemented, tested numerically against concrete cases, and documented with its technical justification — rather than presented as definitively solved.

Der bedeutsamste Teil dieses Projekts ist nicht die Berichtserstellung — es ist der kritische Audit-Zyklus, der es begleitet hat. Eine professionelle Systemprüfung (im Code und README referenziert) identifizierte präzise Schwachstellen aus der aktuellen Quant-/LLM-Literatur (Look-Ahead-Bias, korrelierter Debatten-Bias, unkalibrierter Konfidenzwert), und jede Korrektur wurde implementiert, numerisch an konkreten Fällen getestet und mit ihrer technischen Begründung dokumentiert — statt als endgültig gelöst dargestellt zu werden.

Concrete example: the confidence score is only shown at a given level because it follows a verifiable formula (agreement between factors, magnitude, technical adjustment, audit cap) — tested against edge cases (contradictory factors → neutral confidence at 50, not a misleading average).

Konkretes Beispiel: Der Konfidenzwert wird nur deshalb auf einem bestimmten Niveau angezeigt, weil er einer nachprüfbaren Formel folgt (Übereinstimmung zwischen Faktoren, Magnitude, technische Anpassung, Audit-Obergrenze) — getestet an Grenzfällen (widersprüchliche Faktoren → neutrale Konfidenz bei 50, statt eines irreführenden Mittelwerts).

The confidence formula, in codeDie Konfidenzformel im Code

Ausschnitt aus debate.py — die Funktion, die belegte LLM-Faktoren in einen nachprüfbaren Bias- und Konfidenzwert überführt. Der Docstring erklärt die Begründung, nicht nur die Mechanik.

def _compute_fundamental_score(factors: list[dict]) -> tuple[str, int, dict]:
    """
    Computes bias and confidence IN CODE from the sourced factors
    supplied by the LLM — never the other way around. This is the direct
    fix for the "opaque fundamental score" problem: every confidence
    point is traceable to a sum of named, cited factors, not a
    holistic black-box judgment.

    Formula (deliberately simple and auditable):
    - bias: average score > +0.3 -> bullish, < -0.3 -> bearish, else neutral
    - confidence = 50 (neutral base) + up to +30 for average factor
      magnitude + up to ±20 for agreement between factors (factors that
      contradict each other must lower confidence, even if the average
      leans one way)
    """
    scores = [max(-2, min(2, f["score"])) for f in factors
              if isinstance(f.get("score"), (int, float))]

    if not scores:
        return "neutral", 0, {"total": 0, "avg": 0, "agreement_ratio": 0, "n_factors": 0}

    total = sum(scores)
    n = len(scores)
    avg = total / n

    if avg > 0.3:
        bias = "bullish"
    elif avg < -0.3:
        bias = "bearish"
    else:
        bias = "neutral"

    same_direction = sum(1 for s in scores if (s > 0) == (avg > 0) or s == 0)
    agreement_ratio = same_direction / n

    magnitude = min(abs(avg) / 2, 1.0)  # max score ±2 per factor -> normalized 0-1
    confidence = 50 + magnitude * 30 + (agreement_ratio - 0.5) * 40
    confidence = int(round(max(0, min(100, confidence))))

    return bias, confidence, {
        "total": round(total, 2), "avg": round(avg, 2),
        "agreement_ratio": round(agreement_ratio, 2), "n_factors": n,
    }
06 — Technical Validation & LimitationsTechnische Validierung & Einschränkungen

What has been validatedWas validiert wurde

Tested end-to-end with the full pytest suite and DRY_RUN mode against real market data sources. Three things aren't proven yet:

Durchgängig getestet mit der vollständigen pytest-Suite und dem DRY_RUN-Modus gegen echte Marktdatenquellen. Drei Dinge sind noch nicht belegt:

  • Real-world reliability: the backtesting module exists but hasn't run on real market data over a meaningful period (bar set: 100+ resolved predictions, 3 months minimum, before any conclusion).Zuverlässigkeit unter realen Bedingungen: das Backtesting-Modul existiert, lief aber noch nicht über einen aussagekräftigen Zeitraum auf realen Marktdaten (Maßstab: 100+ aufgelöste Vorhersagen, mindestens 3 Monate, vor jeder Schlussfolgerung).
  • Confidence calibration: formula weights chosen by engineering judgment, not regression on historical data. The walk-forward protocol is ready for this, but hasn't run yet for lack of accumulated data.Konfidenz-Kalibrierung: Gewichte der Formel nach Ingenieursurteil gewählt, nicht per Regression auf historischen Daten. Das Walk-Forward-Protokoll ist dafür bereit, lief aber mangels angesammelter Daten noch nicht.
  • Scope: not an autonomous trading system — no order execution, no global portfolio management (qualitative correlations only, no covariance matrix). CFTC contract names for the retail positioning module are flagged as "to verify manually" rather than treated as reliable by default.Umfang: kein autonomes Handelssystem — keine Orderausführung, kein globales Portfoliomanagement (nur qualitative Korrelationen, keine Kovarianzmatrix).
